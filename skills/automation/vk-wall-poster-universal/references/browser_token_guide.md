# VK API & Browser CDP Architecture Guide

Справочное руководство по внутренней архитектуре работы скилла через CDP-сессию браузера и прямое VK API.

---

## 🎯 Архитектура сессий и авторизации

При работе через браузер (Chrome / Yandex / Vivaldi / Edge / Firefox) скилл взаимодействует со страницей ВКонтакте по протоколу Chrome DevTools Protocol (CDP, порт `9223`):

### 1. Извлечение токена сессии
* Из активной вкладки ВКонтакте извлекается токен сессии из `localStorage`:
  ```javascript
  localStorage.getItem('6287487:web_token:login:auth')
  ```
* Этот токен валиден в контексте браузера владельца / администратора сообщества.

### 2. Выполнение запросов к VK API
* Запросы выполняются методом `POST` с заголовком или телом `multipart/form-data` и параметром `access_token`.
* Для предотвращения CORS-блокировок запросы выполняются внутри активной вкладки через `fetch` или `XMLHttpRequest`.

### 3. Загрузка медиа и публикация на стену
1. `photos.getWallUploadServer(group_id="YOUR_GROUP_ID")` -> получение `upload_url`.
2. Загрузка файла изображения бинарным `POST` на `upload_url`.
3. `photos.saveWallPhoto(group_id="YOUR_GROUP_ID", photo=..., server=..., hash=...)` -> сохранение и получение `photo{owner_id}_{id}`.
4. `wall.post(owner_id="-YOUR_GROUP_ID", from_group=1, message=..., attachments=..., publish_date=...)`.

## 🔄 Преимущества CDP-метода

- **Zero-Config**: Не требует создания и выпуска приложений и сервисных токенов.
- **Обход ошибки IP (Error 5)**: Запросы отправляются с IP-адреса и контекста браузера пользователя.
- **Универсальность**: Поддерживает публикацию от имени группы и от имени пользователя на любую доступную стену.
